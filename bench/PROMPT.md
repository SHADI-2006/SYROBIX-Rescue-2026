# البرومبت الأصلي لأداة الفحص (Bench Tool)

هاد النص اللي انبنت عليه أداة الفحص بمجلد `bench/`. احتفظ فيه كمرجع، وإذا بدك تطلب تعديل
كبير، عدّل هون وابعته من جديد.

---

اقرأ CLAUDE.md أولاً. احكي معي بالعربي ببساطة (أنا طالب)، وقبل كل خطوة قلّي بجملة شو رح تعمل وليش.

المهمة: ابنِ "أداة فحص عتاد" (Bench Tool) منفصلة تماماً عن الـ firmware الأصلي، فيها:
(أ) برنامج صغير للـ ESP32-S3، و(ب) واجهة ويب بملف HTML واحد بتفتح بـ Chrome/Edge وتحكي مع الروبوت عبر Web Serial.
الهدف: أفحص كل قطعة لحالها وأعرف إذا شغّالة أو معطّلة، وأغيّر القيم وأشوف النتيجة فوراً، وأطلع أرقام جاهزة للصق بـ Config.h.

== القواعد ==
1. لا تعدّل أي ملف داخل src/. كل شي جديد داخل مجلد bench/ بمشروع PlatformIO خاص فيه (bench/platformio.ini, bench/src/main.cpp, bench/web/index.html). الشرط: يبني بـ `pio run -d bench` حتى لو الـ firmware الأصلي فيه أخطاء.
2. استقلال كامل: لا تستخدم كلاسات الـ firmware (LineArray, LidarBank...). اتكلم مع العتاد مباشرة (analogRead, Wire, مكتبة Pololu VL53L1X, Adafruit PCA9685). السبب: إذا قال الفحص "الحساس خربان" لازم يكون العتاد فعلاً، مو غلط بكودي. خذ كل الدبابيس والعناوين من src/Config.h (Pins, PcaChannels, Hw, Tof). إذا Config.h ما بيترجم لحاله، انسخ القيم مع تعليق يشير لمكانها.
3. الأمان (إلزامي):
   - كل المخارج مطفية عند الإقلاع، STBY=LOW.
   - Deadman: أي أمر موتور بيعيش 400 ms فقط. الواجهة بتجدّده كل 150 ms. إذا انقطع الاتصال أو انسدّت الصفحة الموتورات بتوقف.
   - سقف PWM افتراضي 40%، ورفعه يحتاج تأكيد صريح بالواجهة.
   - زر STOP أحمر كبير + مفتاح Space = إيقاف فوري لكل شي.
   - السيرفو: حد أدنى/أعلى من Config.h، وحركة تدريجية (slew)، ولا تتحرك بالإقلاع.
4. لا واي فاي ولا بلوتوث. لا تلمس منطق المسابقة.
5. لا تخترع أي قيمة قياس. إذا لقيت حاجة ناقصة اسألني.

== البروتوكول ==
نص ASCII سطر بسطر، 460800 baud. أوامر من الواجهة، وتليمتري JSON سطر بسطر ~20 Hz. وثّقه بملف bench/PROTOCOL.md.

== العناصر (كل عنصر له رقم ثابت بالواجهة) ==
M1 موتور يسار، M2 موتور يمين، E1/E2 encoders، L0..L7 حساسات الخط، T1 ToF أمامي، T2 ToF يسار، T3 ToF يمين، G1 الـ IMU (gyro+accel)، S1 سيرفو الذراع، S2 سيرفو القبضة، D1 LED الحالة، B1 البزّر، C1/C2 حساسا اللون، BTN زر START، P1 حالة PCA9685.

== الفحوصات المطلوبة ==
- G1 (الأهم لأني ما بعرف وضعه): اقرأ WHO_AM_I وبيّن القيمة (MPU6500 المتوقع 0x70) مع حكم بسيط. اختبار "ثبات 3 ثواني": bias والضجيج (std) لكل محور، وحكم OK/مشبوه مع شرح المعيار. عرض yaw المتراكم: ألف الروبوت بإيدي 90°/360° وبيّن الزاوية، وبيّن إشارة الاتجاه (لفة يسار لازم تعطي موجب) لأحدد IMU_YAW_SIGN. عرض ميلان roll/pitch من الـ accel. اكشف القراءات المتجمّدة أو الصفرية.
- T1..T3: إعادة تعيين العناوين عبر XSHUT مثل الـ firmware (0x30/31/32). لكل حساس: mm، status، قوة الإشارة. "مساعد المحاذاة": أحط الروبوت قدام حيط مسطّح، وأدخل المسافة الحقيقية بالمسطرة، والواجهة بتحسب الخطأ (متوسط/أدنى/أعلى/std خلال 2 ثانية) وتحكي إذا الحساس مايل (أدنى قراءة أثناء ما أدير الروبوت شوي = الاتجاه العمودي).
- L0..L7: أعمدة حيّة للقيم الخام، وأزرار "التقاط أبيض/أسود" لتبيّن الفرق وإذا الحساس غير صالح، وموقع الخط -1..+1 من الصف الأمامي (0..5) بنفس طريقة LineArray.
- M1/M2: منزلقات PWM لكل جهة، عدّاد encoder حي مع reset، اختبار اتجاه (نبضة 500 ms بقوة منخفضة) يبيّن إذا الاتجاه والـ encoder منطقيين ويقول إذا في تبديل يمين/يسار، و"لاقط deadband": يرفع PWM تدريجياً لحد ما الـ encoder يتحرك ويعطيني الرقم (لـ PWM_MIN_MOVE).
- S1/S2: منزلق + خانة زاوية + أزرار ±1/±5. أحفظ "مواضع مسمّاة" (ذراع فوق/تحت، قبضة مفتوحة/مغلقة) وصدّرها كنص جاهز للصق بـ Config.h.
- D1/B1/P1: أزرار تشغيل/إطفاء، بيب بمدة، وحالة PCA9685 (ACK، قراءة MODE1/PRESCALE).
- C1/C2: قيم خام R/G/B/clear حيّة، مع اختيار أي رأس.
- BTN: حالة الزر حية.
- اختياري ذاتي (بدون لاب توب): ضغط BTN بعد الإقلاع = عد تنازلي 5 ثواني مع بيب، ثم تسلسل موتورات قصير بـ PWM منخفض، ثم توقف. القيم ثوابت بأول main.cpp مع تعليق.

== الواجهة ==
ملف HTML واحد بدون اعتماد على الإنترنت (لا CDN)، ثيم داكن، تبويب أو بطاقة لكل عنصر برقمه، شارات حالة OK/تحذير/فشل، لوحة "قيم جاهزة لـ Config.h" تجمّع كل الأرقام اللي قسناها، تسجيل CSV قابل للتنزيل، وزر Connect (Web Serial). وضع تجريبي ?mock يحاكي الروبوت بدون عتاد لأتأكد إن الواجهة تشتغل. إذا Web Serial ما اشتغل من file:// أعطني أمر python -m http.server بسيط.

== التسليم ==
1. ابنِ البرنامج فعلياً بـ `pio run -d bench` وصلّح الأخطاء.
2. جرّب الواجهة بوضع mock وقلّي شو اختبرت.
3. اكتب لي بالعربي ترتيب الفحص: (آ) USB فقط بدون بطارية: IMU والـ ToF والخط واللون. (ب) بطارية الموتورات والدواليب بالهوا: الموتورات والـ encoders. (ج) UBEC متصل: السيرفوهات. (د) الأرض آخراً.
4. ممنوع commit. لا تمسح ملفاتي.
